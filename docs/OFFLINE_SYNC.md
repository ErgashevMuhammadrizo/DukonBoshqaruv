# Offline protocol
Local SQLite `operations` durable queue stores stable UUID, JSON payload, retry count, status, last error. POST `/api/v1/sync/push/` accepts `{operations:[{operation_id,type:'sale',payload:{items,cash,card,discount}}]}` and returns per-item ack or conflict. Ack is recorded before local row is marked `ack`. Conflict preserves local row for review. Transaction sale and server sync op are atomic. Pull currently returns full current catalog (not incremental). Concurrent offline sales can oversell; server rejects with conflict. Device clocks do not confer subscription entitlement; expiry policy and recovery are incomplete. No background timer currently runs; sync is manually invoked by user.
